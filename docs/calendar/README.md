## 能力边界

- 公历日期与中国农历/生肖/二十四节气；算法支持范围为 1901-01-01 至 2100-12-31。随包日别资源目前声明已发布年份 2025、2026；其他年份不得冒称法定安排已发布。
- 系统基线 → 系统校正 → 上级业务 → 当前业务 → 本人个人覆盖，后者在各自授权范围内优先。查询返回字段来源/版本；底层变化只产生待复核，不静默丢失个人意图。
- 六个可覆盖字段：农历、生肖、节气、日期政策、展示标签、展示备注。用户选择 SET（设置）、CLEAR（隐藏/清空）、INHERIT（恢复下层）。个人覆盖只对本人有效，业务草稿发布后才对有权读者有效。
- 私人单次日程与托管日程；托管范围角色为 READER / EDITOR / PUBLISHER。平台管理员不自动获得业务内容权或其他人的私人内容。
- 上游通过 `calendar.api` 投影具体事件：创建/更新/调课/取消/重试。Calendar 不负责校园排课算法，也不依赖 Campus 类型。
- 年度 CSV 的上传、校验、差异、审核、发布在内网可执行。CSV 只维护日期政策，不是事件批量导入，也不是六字段通用导入。

非目标：RRULE 重复展开、资源冲突排课、通知/邀请/订阅、原生 XLSX、运行时远程插件、千/万级作业调度或生产并发 SLA。

## 快速验证

在仓库根使用既有 JDK 25 和 Maven wrapper；Docker 必须可用于 Testcontainers：

```bash
./mvnw --batch-mode verify
RUN_CALENDAR_PERF=true ./mvnw --batch-mode verify
cd apocalypse-web
pnpm check
```

macOS 非默认 socket 设置见根 [README](../../README.md)；不把集成测试指向真实环境。第二条是显式性能验证：默认测试会跳过该例，显式运行才生成 8 层/10,000 覆盖/50,000 事件夹具。当前 500 条后台同步预算由用户临时批准为本机 p95 ≤ 5 秒，数据量增长必须重新评估。

功能验收步骤、命令执行结果及已知限制集中在证据索引；不要把 Linear Done 或本地绿测当成已部署证明。
