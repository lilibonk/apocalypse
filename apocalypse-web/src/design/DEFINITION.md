## LIL-85 · 2026-09-08 生效的品牌角色替换

用户已授权以 **Three.js + WebGPU 软体史莱姆** 替换 Mint Bonk。以下新契约取代本文旧版章节中关于 PixelOrb 像素母版、整像素运动、禁止 Canvas、旧角色识别特征及登录 PixelWave 背景的规定；后文保留旧版设计决策的追溯记录，数据表面、静态签名、权限/表单与通用浮层规范不变。方案证据见 [solution-fit.md](../../docs/brand-slime/solution-fit.md)。

- 唯一目标图：`docs/brand-slime/target-v1.png`。青绿、宽圆的半透明凝胶体，柔软扁平的底部、隐约可见的内部气泡、柔和窗形高光与无形桌面的接触阴影；两只黑豆眼和一张小嘴。无触角、腹斑、手脚、像素描边或运行时换肤。
- `PixelOrb` 保留调用兼容，渲染实现在 `effects/webgpu/slime/`；状态仍为 `idle / waiting / success / error / sleeping`。状态表情、局部按压、拉伸与落地挤压均使用同一表面形变；五官不能浮在身体之外。
- 合法容器尺寸为 **384 / 256 / 128 / 64 / 32**，非法值开发环境 throw。容器遵守 4px 网格；实时表面不做像素量化。384 为桌面主视觉，256 为紧凑交互舞台，128/64/32 默认采用新角色静态海报；隐藏的响应式分支不得申请 GPU。
- 主视觉先截图对齐目标图，才增加按压、拎起、轻重力、落地与带阻尼的回弹。进入密码框时闭眼，不干扰输入和认证逻辑。
- 运行时限定 Three.js WebGPU；显式 `Renderer + WebGPUBackend`，不提供 fallback。无 WebGPU、初始化失败或设备丢失使用新角色海报并给出明确提示，不声称静态降级满足 60 FPS。
- `prefers-reduced-motion` 与全局动画开关均生效，关闭时不申请 GPU。隐藏/离屏暂停，卸载清理监听、观察器、rAF 与 GPU 资源；小尺寸空态不创建多实例设备。
- 材质颜色由 `tokens.css` 的 `--slime-*` sRGB token 统一提供：亮色 mint / 暗色冰翡翠绿自动切换，身体、衰减、散射、灯光和静态海报保持同源；不跟随外观实验室 accent 或历史 skin。几何/物理常量只在引擎域内。
- 2026-09-08 暗色对比度修订：亮色配方不变；暗色身体 `#91efd0`、透射衰减 `#45b892`、散射 `#39b889`，浅薄荷光 `#effff5` / 环境 `#a3c7b9`，深墨绿五官 `#031610`。目标是亮玉石般的内部明度、深浅分明的脸部与柔软轮廓，避免灰青一片或荧光白亮块；保留凝胶透明度和全部交互，海报从同源场景重导出。
- 2026-09-08 最终范围调整：登录不展示 PixelWave；既有 letterpress 浪潮仅在开发态“外观实验室 → 动效实验室”通过默认关闭的开关预览，收起或关闭实验室即卸载。生产不暴露该开关，登录不消费它。透明 WebGPU 画布、gaze、BrandSignature、文案、主题/语言与认证生命周期保留，PageLoading/按钮的 PixelScale 不变。
- 登录恢复 gaze opt-in：眼睛平滑跟随鼠标、沿同一皮肤重新定位；闭眼/静态时居中。内部气泡为细小、非金属的透明气泡，分布在体内（含五官后方），缓慢单向上浮与微小横漂，边界淡出后重生；不做显眼的三轴往返/亮珠圈，并受软体形变约束。鼠标按压不显示焦点框，Tab/键盘仍有明确焦点。
- 海报必须来自新目标/已对齐的 3D 场景，不使用旧 Mint Bonk 图。旧 PNG、sprites/skins 导出仅为历史回滚/下游兼容保留，不进入现有产品渲染。
- 交付包含同构图比较、明暗/窄屏/键盘/状态/降级检查、实际后端与明确设备环境的 60 秒性能记录，以及 `pnpm check`。通过自动验证后交给用户人工验收，不自动宣称人工通过。

## 历史设计定义（2026-08-30 至 2026-09-03）

生效日期：2026-08-30。产品定位是服务年轻企业团队的通用 Web 管理脚手架，不是服务监控或可观测性产品。正式品牌签名（静态图形标 + APOCALYPSE 字标）、favicon 与 PixelOrb 吉祥物严格分离：静态签名用于登录页首、侧栏和产品署名；吉祥物只作为“值守向导”出现在登录、空态、成功与异常反馈。品牌主色在正式产品中固定为 mint，批准的角色稿不得被 accent 或历史皮肤设置运行时换色。Canvas PixelWave 禁止在稳定的表单、表格、权限树或审计信息上常驻；Dialog、AlertDialog 与 Sheet 统一由 `PixelDialogMotion` 用 Motion 时间轴让真实标题、正文与操作区穿过固定的不规则像素波前。首屏标题从 100ms 起进入，最晚约 720ms 完成；不存在可选旧分支或额外视觉 DOM。禁止用全表面遮罩、电路折线、散点粒子或长时间空白等待制造品牌感。PixelBean / PixelTide / RetroGrid 已弃用，转向规格见 `docs/pixel-wave-spec.md`。

## 管理工作台信息层级（2026-09-03 人工验收补充）

- 页面只有一个一级标题，标题下是一句面向业务用户的说明；上下文选择与操作独立成工具栏，主内容从分隔线之后开始。表单阅读宽度受限，不沿超宽屏拉成整行。
- 普通列表/月历是主层；查看对象在 Dialog（短编辑/确认）或 Sheet（长详情/关联信息）中打开，禁止在列表底部追加详情并要求用户滚屏寻找。详情标题、可关闭入口、独立滚动正文不可缺少；关闭返回触发器。复核/编辑工作台可采用有明确名称与选中上下文的主辅栏。
- 编辑、预览/复核、历史属于不同任务，用有名称的 Tabs 或主辅栏区分；历史、来源标识、内容校验码默认折叠。不可将多个无关联表单按同权重连续平铺。
- 上下文工具栏、分区标题、字段组、操作栏形成四级层次；同一操作区域只强调一个主操作，危险操作独立确认。标签必须常驻，不得以 placeholder 替代。
- 标准枚举使用共享 Select，弹层对齐触发器并跟随明暗主题；无可选内容时禁用并解释。日期、月份、本地日期时间使用共享 DatePicker，禁止在业务页面直接使用原生选择/日期弹层。
- 月格最多呈现日号、短农历（初一显示月份，其他显示日名）、节日/节气；完整年月与来源放详情。“来源变化待确认”要说明当前值仍保留，不用内部字段、状态枚举或哈希代替解释。
- 侧栏首次进入工作台时目录收起，深链只展开当前目录；叶菜单精确匹配，选中、hover 和键盘焦点是不同状态。
- 验收必须包含真实浏览器的空态、有数据、明暗主题、窄屏、键盘及浮层焦点恢复；静态渲染/接口测试不是 UI 验收替代品。

## 0. 分层（先读这一节）

两套语言并存，禁止混用。

| 层           | 用在哪                                                               | 气质                                                |
| ------------ | -------------------------------------------------------------------- | --------------------------------------------------- |
| **数据表面** | 表格单元格、表单控件、对话框、命令面板、设置项（吉祥物预览除外）     | shadcn/new-york，可读、密；瞬时浮层允许快速像素装配 |
| **品牌表面** | 登录舞台、全局 PageLoading、空状态、不确定进度、操作成功的一次性反馈 | 像素、整数格、锐利、鲜明                            |

正式图形标 / 字标属于静态产品签名，不是 PixelOrb 挂载点。侧栏与 favicon 禁止使用吉祥物。

不要把管理台做成低帧率 8-bit 皮肤。数据本身保持稳定，像素表达集中在进入、退出、层级切换和操作反馈；品牌表面不再使用扫光圆角 skeleton。

## 1. 网格与锐利度

- [ ] 基础格子 **4px**。密度缩放（`--spacing`）之后，品牌表面的位移/尺寸仍落在整数格上。
- [ ] 吉祥物只允许合法阶梯 size（`256 / 128 / 64 / 32`，32 为图标态）。非法 size：**开发环境 throw**，生产打 error 并吸附最近合法值。
- [x] 品牌母版是 **1536×1024 的 3×2 透明状态设计稿**；每格 512×512，256/128/64/32 四档均以精确单格裁切显示。登录桌面 256、登录移动 / 空态 128、紧凑空态 64、消息图标 32。
- [x] 运动只允许作用于状态帧容器的整像素位移；禁止代码重绘角色、整图亚像素缩放、连续旋转或柔性滤镜造成像素发糊。
- [x] 吉祥物图片使用 `image-rendering: pixelated`；组件不得创建 Canvas 或常驻 rAF。登录 idle 允许单一 passive `pointermove` 监听，只更新两枚原稿眼部高光的整像素 CSS 位移。

当前合法 size：`256 / 128 / 64 / 32`。  
常用阶梯：登录桌面主视觉 256、登录移动 / 宽松空态 128、紧凑空态 / 开发预览 64、消息 / Toast 图标 32。侧栏使用静态品牌标，不占用吉祥物尺寸阶梯。

## 4. 吉祥物

- [ ] 全局唯一品牌吉祥物：`src/effects/PixelOrb/`，对外组件名保留，视觉必须忠实使用批准设计稿 Mint Bonk。识别特征固定为长软左触角、短圆右触角、梨豆形薄荷身体、深青像素描边、白色腹斑、腮红和短手脚；不得以 Canvas、SVG、CSS 或代码栅格重绘近似形象。状态词表固定：

  `idle | waiting | success | error | sleeping`

- [ ] `thinking` 仅 2 期 Agent 化身使用，当前不实现，不得挪用；`loading` 语义并入 `waiting`。
- [x] 形状源：`public/brand/mint-bonk-design-sprites-v1.png`。上排依次为 `idle / waiting / success`，下排前两格为 `error / sleeping`，右下背面设定稿不进入运行状态。
- [ ] 状态切换只改变裁切坐标；`skin` 兼容参数不得改变素材、颜色、五官或轮廓。idle `gaze` 仅移动从批准稿裁出的两枚眼部高光，静态高光由同一批准稿的黑色眼内裁片覆盖。
- [ ] 降级（`prefers-reduced-motion` 或 `html[data-motion=off]`）：直接显示当前状态的批准静态帧，视线回中，零监听、零 rAF。
- [ ] 氛围层唯一语言：`src/effects/PixelWave/`（v2.11 连续铅字浪潮：**基态 = 干净白/黑背景**。登录 `appearance="letterpress"` 使用 32px 固定节距（28px 顶面 + 4px 缝隙）的完整网格；每 7s 从不与上一波重复的随机角点发射欧氏距离波前，2.4s 扫过全场，0.09s 快速抬升后按 0.38s 时间常数指数回落。波包阈值以上的格子全部参与。**每波换一张噪声图**：随机 session seed 与波序号派生当波 seed，同时驱动低频距离扭曲、≤0.045s 点火抖动、浮雕高度与空间连续色带；同一波稳定，相邻波与重复进入均为新形状。铅字顶面严格绘制为 `--background`（亮色白底白块、暗色黑底黑块），抬升侧壁以 `--border` 与低透明 `--foreground` 灰阶叠加表达深度，程序化 oklch 彩色流光只画剪影边缘，禁止染色顶面。PixelWave 只允许登录舞台、全局加载、进度和一次性反馈；CRUD 浮层不得挂载 PixelWave。`PixelScale` 是同目录下的一维操作反馈形态：以 CSS `steps()` 驱动 6/12/16 根离散高度像素柱，分别用于按钮、局部与页面加载，不构成第三套品牌语言。降级时停驻为静态音阶；Canvas PixelWave 的 reduced-motion 与 P10 低帧仍为零渲染纯背景。组件恒 pointer-events-none、无鼠标或点击交互。
- [ ] `effects/PixelBean/` 与 `effects/registry/RetroGrid/` 已弃用（历史兼容保留），新代码禁止引用。

## 5. 动效

组件级实现、编排顺序与验收清单见 [`MOTION.md`](./MOTION.md)。本节定义边界，`MOTION.md` 定义执行契约。

选最弱可用工具。能 CSS 不 JS，能 motion 不 GSAP，能 GSAP 不 WebGL。

| 层  | 范围                                                               | 工具                                                         |
| --- | ------------------------------------------------------------------ | ------------------------------------------------------------ |
| 0   | hover、显隐、颜色、位移                                            | CSS / Tailwind                                               |
| 1   | 页面过渡、小型信息组分拍、量化位移                                 | `motion`                                                     |
| 2   | 吉祥物状态、像素格编排                                             | `effects/PixelOrb`、`effects/PixelWave`、`effects/` 下品牌件 |
| 禁  | 表格行 / 树节点逐项装饰动效、低帧卡顿、落地页流体光标、Lottie/Rive | —                                                            |

白名单场景：页面过渡、Dialog / AlertDialog / Select / Dropdown / Tooltip / 命令面板 / 抽屉进出、浮层内最多三个信息分区的快速装配、品牌表面（登录/空态/加载/进度/成功反馈）、PixelOrb / PixelWave。

通用管理台只使用一组短促节拍，事实来源为 `tokens.css`，`design/motion.ts` 是 motion 的秒值投影：

| 语义               |          时长 | 用途                              |
| ------------------ | ------------: | --------------------------------- |
| feedback           |         100ms | hover、press、选中与层级后退      |
| exit               |         120ms | 折叠退出、遮罩与浮层退出          |
| enter              |         200ms | Tooltip / Select / Dropdown 进入  |
| layer enter        |         180ms | Dialog / AlertDialog 空白外壳进入 |
| standard           |         180ms | 页面进入、真实信息层级展开        |
| panel exit / enter | 160ms / 300ms | Sheet / Drawer 退出与进入         |
| CRUD reveal        |         500ms | 全部浮层真实内容的恒速像素波前    |

进入统一用 `cubic-bezier(0.16, 1, 0.3, 1)`，退出统一用 `cubic-bezier(0.4, 0, 1, 1)`；Dialog / AlertDialog 外壳使用 `96.5% → 100.8% → 100%` 的快速几何装配，Sheet 保留真实停靠边位移。所有基础浮层强制启用 `PixelDialogMotion`，标题从 100ms、正文从 150ms、操作区从 220ms 起进入，最晚约 720ms 完成。八个水平分区使用同一组固定、非随机、推进距离不一致的 polygon 关键帧，以 500ms linear 曲线直接裁切真实内容；波前不得复用前快后慢的 enter 曲线吞掉中间帧。禁止添加独立能量轨、端点、顶部进度条或任何稳定态装饰。禁止全表面实色遮罩、PCB 折线、散点粒子、锯齿外壳、棋盘扫描条、四角装饰框、稳定态像素边线或可感知空白外壳。普通数据卡片不伪装成折叠卡片，只允许 hover / press 反馈；卡片展开只用于确有信息层级的 disclosure 区域。

Rive / Lottie 仍禁：二进制资产无法按「帧即数据」用代码迭代。解禁属宪法 §10，须另案。

## 9. 品牌签名与吉祥物分工

旧方案把正圆球体、圆眼与正式 logo 混为同一形象，既同质化又让管理台每个页面都像品牌展示页。当前方案拆成两套职责明确的资产：

- **正式签名**：断裂方框 + mint 信号芯的静态图形标，配 APOCALYPSE 字标。用于 favicon、侧栏、登录页首与产品署名，不眨眼、不跟随鼠标。
- **吉祥物**：批准设计稿 Mint Bonk 只承担登录、空态与结果反馈；五个状态均直接使用固定透明母版，idle 只移动原稿眼部高光实现视线跟随，不运行时重画五官或身体。
- **管理正文禁入**：工作台能力入口、权限树、表格、日志与设置正文不常驻吉祥物，也不把状态审计包装成品牌图。
- **登录锁定**：桌面端只保留一个 256px 主视觉；右侧安全访问表单为独立实色数据表面，避免 PixelWave 干扰输入。

## 10. v2.9 登录铅字浮雕决策

- **顶面同色**：登录舞台的 PixelWave 不再用半透明彩色填充覆盖块面。顶面只用 `--background`，因此亮色模式是白底白色铅字块，暗色模式是黑底黑色铅字块。
- **深度分层**：点火窗内以快速抬升、缓慢回落的离散高度驱动几何位移；侧壁只用 `--border` / `--muted-foreground` 的灰阶阶梯，彩色只允许出现在 2px 剪影线芯与极淡外沿。
- **隔离表单**：桌面 PixelWave 只铺品牌舞台，不铺安全访问表单；移动端只铺紧凑品牌头。表单维持纯数据表面，避免流光穿过输入与按钮。
- **兼容现有挂载点**：`appearance="letterpress"` 为登录专用渲染器；PageLoading 与空状态默认 `flowlight` 不变，不另起第三套动效引擎。

## 11. v2.10 图 3 忠实度纠偏

图 1/2 暴露出 v2.9 的模型错误：`35%` 参与率、0.5s 硬点火和对角走廊只产生少量空心框，无法形成研究演示图 3 的连续铅字浪潮。本节推翻登录 `letterpress` 的场模型，但保留同底色顶面与主题材质。

- **完整网格，不做随机抽样**：波包阈值以上的格子 100% 参与，连续波峰轮廓必须可读。
- **欧氏波前，不是方形环**：每波从随机角点向全场径向扩散；相邻波不得复用角点。
- **长尾高度场**：使用 `bump = (1 - exp(-u/0.09)) × exp(-u/0.38)`，让波峰之后仍保留大面积不同高度的柱体；低于 0.03 才归零。
- **固定铅字规格**：登录 fill 模式使用 32px 节距、28px 顶面、4px 缝隙，不再按 48 列等分成细小方框；最大挤出约为顶面边长的 1.45 倍。
- **布局边界**：浪潮可充满品牌舞台，但右侧登录表单仍以实色表面隔离；文字信息块可用同底色遮挡层保证可读性。
