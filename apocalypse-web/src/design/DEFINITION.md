# Apocalypse Web 设计定义（V2 宪章）

> **唯一直源**：本文件定义 Apocalypse 管理台（覆盖 `system`、`calendar` 及全部下游业务模块）的唯一前端设计语言、四大页面心智原型、三级表面材质、顶置活水流转语法与可访问性标准。`src/design/tokens.css` 是本文件的 CSS 变量投影，[MOTION.md](./MOTION.md) 与 `src/design/motion.ts` 定义同源物理动效，自动化门禁（`spatial-architecture.test.ts`、`insight-tokens.contrast.test.ts` 与 Playwright 浏览器套件）强制执法。

---

## 1. 核心设计哲学：静谧精密 × 活水业务流（Quiet Precision × Living Flow）

企业级管理台的高级感来自**极高的信噪比（Signal-to-Noise Ratio）**：平时界面如精密仪器般安静克制，一旦发生业务选择、筛选或变更，关联脉络与数据结果如活水般顺着因果路径自然浮现。

1. **业务本质优先于容器装饰**：任何图形或布局必须在 2 秒内回答该页面的「唯一根本业务问题」（例如角色管理直接表达「持有人群 → 角色 × 数据范围 → 真实业务能力域」的权力拓扑，禁止使用无业务穿透力的空洞汇总圆环）。
2. **单屏单主透镜（Zero Dual-Paradigm Stacking）**：同一激活视图内，**宏观态势画布（热力图 / 拓扑图）与微观全量数据表严禁上下同屏堆叠**。宏观抓异常与关系，微观查行记录，二者通过轻量右侧快览抽屉或显式视图切换衔接。
3. **导航锚点与正文数据解耦**：
   - **可选模块与快捷任务栏**仍兼容顶置 `<LivingContextBar>`（如 `calendar` 8 页与工作台常用任务区）；
   - **核心管理域与新演进工作区**采用零学习成本的 **原位语义预览与直达 `<EntityPeekLink />`**（基于内置 Radix `HoverCard`，悬停即览摘要、点击直达目标并自动依据目标菜单权限降级为只读文本），避免在顶部反复抄写实体标签；数据表格单元格内仍严禁散落渲染带厚边框的 `<EntityPill>`。

## 1.5 正交三主题世界与五大零位图程序化原语（V2.5 视觉演进）

在不破坏一套 DOM 骨架、四大心智原型与三级表面材质的前提下，全站引入正交视觉维度 `html[data-theme-world="fluid" | "sketchbook" | "obsidian"]`（**产品默认 `fluid`：清透活水玻璃管**）：

1. **`fluid`（清透活水玻璃管 · 默认）**：浅瓷薄荷画布配合高透白卡与四层同源矢量立体玻璃管道（外管投影 → 流体主渐变 → 授权口径线宽流心 → `2.8px` 顶部白光折射高光条）。
2. **`sketchbook`（手绘水彩手账）**：冷压和纸点阵底纹 + 卡片独立 `.sketch-border-svg` 确定性（`mulberry32`）双笔触出锋描边 + 文字层彻底绝缘的全局 `#watercolor-bleed` 湿边水彩积水层 + 法向偏移双岸水彩河道。
3. **`obsidian`（深邃极光夜色）**：深黑曜石暗夜表面 + 高亮生物荧光青绿等离子管道 + `ApoParticleOrb` 规则星云核（自动启用 `.dark` 暗色基线与高对比可读性）。

### 五大零位图可编码原语

- **`<SvgThemeFilters />`**：挂载于 `AppProviders` 根部的零尺寸共享 SVG 滤镜与梯度仓库（`#watercolor-bleed` / `#apo-sketch-ink`），滤镜只作用于装饰边框与流体河道，**文字与等宽编码永远 100% 锐利无模糊**。
- **`<SketchBox />`**：依据容器实测尺寸用 `ResizeObserver` + `mulberry32(seed)` 生成双道手绘墨线与可选湿边底色隔离层（仅 `sketchbook` 世界激活）。
- **`<FluidConduitOverlay />`**：测量 `data-conduit-anchor` 坐标绘制动态三次贝塞尔水路（`ALL` 加粗涌流 / `STANDARD` 标准流 / 未授予虚线或断流），响应容器尺寸与滚动且严格遵循 **`idle rAF === 0`**。
- **`<ApoParticleOrb />` 与 `<SketchApoPeeker />`**：`⌘K` 与工作台快速问答入口采用可卸载 Canvas 2D Fibonacci 3D 粒子球（关闭/隐藏/静态即时停帧，绝不越界导入 `three`）；卡片边沿挂载向量视线跟随 `<SketchApoPeeker />`。
- **`<EntityPeekLink />`**：原位点划线下钻胶囊，依托 `radix-ui` `HoverCard` 在对应主题便签/磨砂卡中预览上下游关系。

全项目所有路由必须且只能归入以下 4 种心智原型之一，严禁跨原型混搭堆叠：

| 原型代号 | 心智原型名称                                         | 解决的根本业务问题                                       | 标准空间骨架                                                                                                            | 严禁出现的反模式                                                                           |
| -------- | ---------------------------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **A1**   | **态势脉冲台**<br>_(Pulse Bento)_                    | 「当前系统整体健康吗？异常集中在哪里？」                 | 单屏视口预算（`100dvh - chrome`）+ 主次分明的 Bento 网格 + `@container main` 自适应                                     | 严禁超出一屏导致底部卡片被裁切；严禁在态势卡下方同屏堆叠分页表格                           |

## 3. 空间层级、三级表面与信噪比减法预算

### 3.1 三级表面材质体系（严禁「白框套白框」）

1. **L0 画布底（`--background`）**：浅色 `oklch(0.972 0.002 260)` / 暗色 `oklch(0.19 0.006 260)`，承载全幅空间舞台与主工作区背景。
2. **L1 业务主面板（`--card` + `--radius-panel: 1rem` + `--shadow-surface`）**：承载一张完整的业务档案或一张主数据表。**L1 面板内部严禁再嵌套带边框和阴影的子白框**，内部区块一律通过留白（`space-y-5`）与 `1px solid var(--border-subtle)` 极细分割线组织。
3. **L2 悬浮与深色证据层**：
   - **导航与悬浮 HUD（`navigation-surface` / `FloatingHud`）**：仅限侧栏、顶栏、空间舞台四角 `fit-content` 浮窗使用适度半透明毛玻璃（无模糊支持时实色回退），正文表格与表单禁用毛玻璃。
   - **深石板墨水舱（`--ink-well: oklch(0.19 0.02 255)` / `--ink-well-foreground: oklch(0.93 0.01 255)`）**：专用于底部未保存草稿条 `DraftBar` 与操作审计 JSON 证据代码块，形成鲜明的「待提交 / 原始证据」视觉锚点。

### 3.2 信噪比「三砍一留」铁律

- **砍掉多重计数器**：每个页面只在顶栏（或唯一主列表头）保留 **1 个主计数**，严禁同时出现「顶栏匹配数 + 左轨本页数 + 底部分页条总数」三重报数。
- **砍掉防御性免责段落**：页面副标题限制在 **18 字以内**（标题自明时省略）；严禁在页面中部或底部铺陈解释性免责长句，确需说明的边界规则统一收进标题旁 `?` 按需气泡。
- **砍掉多余圆角分叉**：全站严格统一为三级圆角：`--radius-control: 0.625rem (10px)`（按钮/输入框/胶囊）、`--radius-panel: 1rem (16px)`（卡片/面板/浮窗，`--insight-card-radius` 同源指向该值）、`--radius-stage: 1.25rem (20px)`（全幅画布外框）。
- **留足主数据呼吸感**：舒适密度（`comfortable: --spacing = 0.25rem`）与紧凑密度（`compact: --spacing = 0.21875rem`）全局一键切换，根字号恒定 `16px`，禁止靠缩小正文字号换密度。

### 3.3 容器查询响应式铁律（`@container main`）

主内容区挂载 `.spatial-main-container`（`container-type: inline-size; container-name: main`），**内部多栏布局断点一律基于 `@container main` 查询**：

- `>= 1280px` 视口：侧栏默认展开；`main >= 68rem` 时主从双栏与宽屏 Bento 完整铺开。
- `1024px – 1279px` 窄桌面：侧栏自动收起为图标轨（可手动展开）；`ResponsiveInspector` 在窄容器下自动转为右侧滑出 `Sheet`，不挤压主表或拓扑画布。
- `< 1024px` 移动/平板：空间拓扑台自动提供等价可操作对象列表，登录页 Milk Cloud 转为顶部 `56px` 紧凑云条。

## 4. 「活水」跨域流转语法（`<EntityPeekLink />` 与兼容 `<LivingContextBar>`）

用户在检视任何业务实体时，无需回退菜单重新搜索，即可在原位或视线第一落点看到上下游关联脉络并一键穿透。

1. **双轨合理共存**：
   - **原位语义预览与直达（`<EntityPeekLink />`）**：依托 `radix-ui` `HoverCard`，将部门名、角色徽标、账号等字段原地升格为带点划线的交互锚点（悬停呈递对应主题快览浮卡、点击携 `EntityRouteIntent` 穿透目标页、无菜单权限时自动退化为只读 `<span>`）。
   - **兼容顶置脉络条（`<LivingContextBar>`）**：在 `calendar` 8 页（保持冻结）与工作台常用任务区继续保留 `role="navigation"`、`data-slot="living-context-bar"` 单行紧凑展示，承载 `EntityReturnPill` 与 `EntityPill`（`size="sm"`）。
   - 当既无来源返回锚点也无有效关联胶囊/动作时，`<LivingContextBar>` 自动返回 `null`，不占高度。

## 5. 色彩、字体、可视化与品牌角色规范

1. **色彩角色纪律（OKLCH 明暗同源双写）**：
   - **Mint 品牌色（`--brand` / `--brand-text`）克制原则**：实底品牌色只用于唯一主行动按钮（Primary CTA）；浅底品牌色（`bg-primary/8` + `--brand-text`）只用于当前激活项、来源锚定行 `data-origin-active` 与因果脉冲路径。
   - **六色语义状态体系**：枚举与 `DictTag` 使用持久化六色（`BRAND` / `INFO` / `SUCCESS` / `WARNING` / `DANGER` / `NEUTRAL`），任何颜色状态必须伴随明确文字标签，正常正文对比度 `>= 4.5:1`，关键图形对比度 `>= 3:1`。
2. **排版纪律**：
   - 标题 `text-xl / text-2xl font-semibold tracking-tight`；正文 `text-sm (14px)`；辅助标签 `text-xs (12px) text-muted-foreground`。
   - 一切计数、金额、耗时、日期时间强制 `tabular-nums`；仅权限编码（`system:user:edit`）、角色标识（`super_admin`）、IP、`jti`、JSON 载荷使用 `font-mono`。
   - 表头使用不透明 `--table-head`；右侧固定列仅在滚动内容压于其下时显示 `--table-frozen-shade` 阴影。
3. **数据可视化真值纪律**：
   - 严禁伪造趋势或显示无接口依据的虚构指标；无权限读取的统计项整项省略而非显示伪 `0`。
   - 热力图严格区分 `0 记录`（`--heat-0`）、`未覆盖未来时段`（`--heat-uncovered-stripe` 中性斜纹）与 `失败集中高危格`（`--heat-failure-stripe` 警示斜纹）。
   - 关系拓扑连线粗细与色调对应真实业务权限（实线高亮 = 含写/治理权 `GOVERN`，细线 = 仅查询权 `READ`，无连线 = 未授权）。
4. **品牌角色与静态签名边界**：
   - 交互式 WebGPU 角色（`Milk Cloud / Apo`，`effects/webgpu/slime/`，明暗同源 `--slime-*` token）严格限定于 `/login` 登录门户（支持密码闭眼、提交等待/成功/失败姿态，无 WebGPU 或动画关闭时优雅降级静态海报，无 WebGL 回退）。
   - 业务管理台侧栏、移动导航、页首与 favicon 统一使用轻量静态品牌图形签名 `BrandSignature`；工作台欢迎区使用静态品牌首图 `BrandHero`；等待态统一使用圆润连续的 `PulseIndicator`。
   - `⌘K` 命令/规则探针及工作台快捷入口使用轻量可卸载 Canvas 2D `<ApoParticleOrb />`（严格零 `three` 导入与 `idle rAF === 0`）；卡片角沿 `<SketchApoPeeker />` 使用纯矢量 SVG（`--peeker-*` token），零位图请求。
5. **状态完整性与可访问性**：
   - `loading`、`success-data`、`success-empty`、筛选无结果、首次错误、刷新错误、权限不可用分别独立表达；`403/404`、撤权、换号按 `sessionEpoch` / `authorizationEpoch` 立即清理缓存、草稿与在途副作用。
   - 所有图标按钮具备明确 `aria-label`；Dialog / Sheet 关闭后焦点返回触发器；200% 缩放、`320px` 窄屏与 `zh/en` 双语下核心流程完整可用。
