# Apocalypse Web 全界面设计风格评审

评审日期：2026-08-28  
范围：本地登录、管理壳层、用户 / 角色 / 菜单 / 部门 / 字典 / 参数、登录日志 / 操作日志 / 在线用户、弹窗、空态、404、明暗主题、色弱模式、桌面与移动端。  
方法：在本地演示环境以管理员身份走查，结合真实页面截图、可访问性树与关键实现约束进行评审；未提交删除、授权覆盖或强退等破坏性操作。

## 结论

当前产品不是“整体很丑”，而是**缺少一个清晰的产品身份**：它同时像 shadcn 组件演示、后台脚手架、像素品牌实验场，三者各自成立，但没有统一服务于管理员的核心任务。

建议把目标风格确定为：**Calm Control Plane / 秩序控制台**。

- 产品人格：冷静、可靠、可审计，遇到高风险操作时明确而不惊慌。
- 品牌人格：可爱极简的像素向导，负责欢迎、等待、空态和结果反馈；不承担日常表格装饰。
- 视觉关键词：编辑式秩序、精密像素、克制中性、单点流光、风险显性。
- 不建议：整站 8-bit 游戏化、任意换强调色、纯黑“炫酷”后台、到处放大吉祥物。

## 评审路径与健康度

| # | 评审步骤 | 健康度 | 核心判断 |
|---:|---|---|---|
| 1 | 桌面登录与品牌首屏 | 有风险 | 分屏逻辑清楚，但留白过大；实测 8 秒内 PixelWave 未出现，品牌舞台显得未完成。 |
| 2 | 移动登录、校验与中英文 | 一般 | 移动重排良好，校验 ARIA 关联正确；切英文后旧错误仍为中文，英文主标题发生视觉截断。 |
| 3 | 主壳层、侧栏、顶栏与页签 | 较弱 | 桌面可用，但内容与 56rem 侧栏之间留下大量空域；多页签是可点击 `div`，缺少 tab 语义，关闭按钮仅 hover 可见。 |
| 4 | 用户、角色、参数等 CRUD 列表 | 一般 | 组件一致、学习成本低；但信息密度与宽屏利用率低，常用/高风险操作都压成一组无文字图标。 |
| 5 | 新增/编辑表单与字段校验 | 良好 | 弹窗结构和错误反馈稳定，移动端表单本体也能重排；必填预期、关闭文案与危险/普通操作层级仍需统一。 |
| 6 | 角色菜单授权 | 严重 | 没有已授权回显，每次从空状态开始，却以“保存整体替换”提交，属于权限误清空风险，不只是视觉问题。 |
| 7 | 菜单树、部门树、字典数据 | 一般 | 结构数据可读，但技术字段和图标动作密集，缺少结构摘要、批量折叠、差异预览与明确的层级引导。 |
| 8 | 登录日志、操作日志、在线用户 | 较弱 | 读表基本顺畅；登录日志/在线用户被 User Agent 拉宽，关键时间和操作列被推到横向滚动区。 |
| 9 | 删除等高风险确认 | 有风险 | 确认文本说明了逻辑删除，但最终“确认删除”仍使用品牌薄荷主按钮，危险语义没有视觉优先级。 |
| 10 | 设置、暗色与色弱模式 | 严重 | 设置抽屉更像能力 Demo；暗色表面层级塌缩；所谓色弱模式是全局 `invert(80%)`，会破坏全部颜色与可读性。 |
| 11 | 管理台移动端 | 严重 | 固定侧栏占去接近一半宽度，页签、标题、筛选和表格被压到不可操作，是当前最明显的响应式阻断。 |
| 12 | 首页、404 与空态 | 较弱 | `/dashboard` 直接进入稀疏 404；空态吉祥物友好但过大，没有“清除筛选”等恢复动作。 |

## 关键截图证据

### 1. 登录：品牌舞台有明确骨架，但氛围层未形成

![桌面登录](.product-design-audit/2026-08-28-full-ui-style/01-login-current.png)

登录页是当前最接近品牌页面的一处：左侧“秩序叙事”、右侧“安全访问”分工正确。问题是左侧面积很大，而 PixelWave 在连续 8 秒采样中均未出现，最终只剩吉祥物、标题与大片空白。移动版重排反而更紧凑。

![移动登录](.product-design-audit/2026-08-28-full-ui-style/02-login-mobile.png)

### 2. 管理壳层：一致，但没有形成工作台层级

![用户管理](.product-design-audit/2026-08-28-full-ui-style/07-user-management.png)

当前宽屏页面把真正的工作区限制在中间约 56rem；侧栏、页签、内容容器都存在，却没有“当前位置—任务—对象—操作风险”的层级。结果更像一个干净的组件样例，而不是高频管理工具。

### 3. 表单：这是当前最成熟的部分

![新增用户校验](.product-design-audit/2026-08-28-full-ui-style/09-user-create-validation.png)

错误颜色、输入边框、字段消息和焦点反馈清楚，登录字段也确认存在 `aria-invalid` 与 `aria-describedby` 关联。建议保留这套基础表单语言，只补齐必填标记、首错聚焦、危险提交样式和一致的中文辅助文案。

### 4. 权限：功能风险高于视觉风险

![菜单授权](.product-design-audit/2026-08-28-full-ui-style/11-role-grant-menus.png)

当前弹窗明确写着“暂无已授权回显接口，每次从空开始，保存整体替换”。这会诱发管理员误清空角色权限。目标交互必须先读取当前授权、显示半选状态、搜索权限、汇总变更，并在提交前展示“新增 / 移除”差异。

### 5. 树与技术数据：需要从“字段罗列”升级到“结构理解”

![菜单管理](.product-design-audit/2026-08-28-full-ui-style/12-menu-management.png)

菜单管理同时承载目录、菜单、按钮、路由、组件、权限串和可见状态。现在虽然都展示了，但没有围绕结构维护建立视觉分组；建议首列承担树主轴，技术字段按“路由 / 权限 / 显示规则”成组，并把新增子级变成带文本的行级主操作。

### 6. 审计与在线会话：关键信息应始终可见

![登录日志](.product-design-audit/2026-08-28-full-ui-style/17-login-log.png)

![操作日志详情](.product-design-audit/2026-08-28-full-ui-style/19-operation-detail.png)

登录日志和在线用户不应把 User Agent 原文作为等权主列。建议压缩为设备 / 浏览器摘要，详情中再展示原文；固定时间、状态和操作列。操作日志详情应对请求参数、结果和异常做格式化、折叠、复制和敏感字段提示，而不是单行原始文本。

### 7. 设置与主题：从产品设置里移除设计系统演示

![界面设置](.product-design-audit/2026-08-28-full-ui-style/21-interface-settings.png)

“能力全集演示（12 项）”“在 `stores/settings.ts` 裁剪”等实现说明不应出现在最终管理产品里。用户层只保留主题、密度、语言；布局、内容宽度、页签、固定头部、灰度、动画、吉祥物皮肤与九种强调色移到“外观实验室”或开发配置。

![色弱模式](.product-design-audit/2026-08-28-full-ui-style/28-color-weak-mode.png)

色弱模式的全局反色不是无障碍方案，应该先下线。正确方向是：状态同时使用文本 / 图标 / 形状，不以颜色为唯一信号，并对常见色觉类型提供经过对比度验证的语义色板。

### 8. 移动管理台：壳层需要改为抽屉，而不是缩小桌面版

![移动用户管理](.product-design-audit/2026-08-28-full-ui-style/26-user-management-mobile.png)

移动端固定侧栏压缩了标题、搜索、表格和操作。建议 `< 768px` 使用顶部栏 + 抽屉导航，隐藏多页签；表格改成关键字段卡片或列优先级模式，行操作固定可见。

### 9. 缺失的首页与恢复路径

![Dashboard 404](.product-design-audit/2026-08-28-full-ui-style/29-dashboard-direct.png)

![筛选空态](.product-design-audit/2026-08-28-full-ui-style/30-empty-state.png)

首页不应是装饰 KPI，也不应不存在。对这个项目，更有意义的是“系统健康 + 安全态势 + 待处理异常 + 快速操作”：最近登录失败、在线会话、近 24 小时异常操作、权限变更、服务依赖状态。404 与空态都应提供明确恢复动作。

### 10. 高风险动作的语义色不应被品牌色覆盖

![删除确认](.product-design-audit/2026-08-28-full-ui-style/31-user-delete-confirmation.png)

删除按钮使用薄荷品牌色，视觉上与“保存”“新增”相同。品牌色只代表主操作；删除、强退、停用、权限覆盖必须使用危险语义，并明确影响对象、作用范围、可恢复性和审计结果。

## 做得好的部分

1. “数据表面 + 品牌表面”的双层思路本身是正确的，适合管理台。
2. CRUD 页面、表单、弹窗和状态标签使用统一组件，交互学习成本低。
3. 登录移动版、表单错误样式、焦点环与错误关联已经有较好基础。
4. 像素吉祥物具备亲和力，适合做等待、空态和结果反馈，不必抛弃。
5. 明暗 token、密度与动画降级已有系统化意识，后续重构不是从零开始。

## 目标风格：Calm Control Plane / 秩序控制台

### 1. 信息架构先于装饰

- 登录后根据角色进入真实工作台，而不是第一个 CRUD 菜单。
- 一级导航按任务域分组：身份与权限、系统结构、配置与字典、审计与会话。
- 页面头部提供对象范围、环境、风险等级与主操作；搜索和筛选紧贴数据，不漂浮。

### 2. 视觉层级

- 中性石墨 / 雾白为 90% 骨架；只保留一个品牌强调色。
- 成功、警告、危险是独立语义色，不能随用户更换强调色。
- 宽屏工作区采用 12 列或可伸缩容器；列表不要再次固定在 `max-w-5xl`。
- 暗色避免纯黑吞没边界，使用至少三档表面亮度和柔和描边。

### 3. 像素品牌的正确位置

- 吉祥物是“值守向导”，不是每张表的主视觉：登录 160–224、侧栏 28–36、空态 64–80、Toast / 进度 24–32。
- 视线跟随只用于登录、空态或显式互动；管理操作时保持静态，避免干扰注意力。
- PixelWave 只用于登录舞台、加载、一次性成功和极轻空态；不得穿过表单、表格正文或审计数据。
- 让“精密像素 + 平滑运动”成为特色，不把整个 UI 做成复古游戏。

### 4. 表格与高风险工作流

- 常规表格：行高 40–44px，操作列固定，常用动作带文字或在更多菜单中按风险分组。
- 审计表格：时间 / 状态 / 对象优先，设备与原始报文进入详情抽屉。
- 权限配置：三态树、搜索、全选子树、已选摘要、变更差异、影响范围确认。
- 空态区分“没有数据”和“筛选无结果”；后者直接提供“清除筛选”。

### 5. 响应式

- `>= 1280px`：完整侧栏 + 宽数据区。
- `768–1279px`：64px 图标轨或可折叠侧栏。
- `< 768px`：顶部栏 + 抽屉导航，关闭多页签；表格使用列优先级、卡片或详情下钻。

## 可访问性评审

已确认的优点：登录校验字段具有 `aria-invalid`，错误文本通过 `aria-describedby` 关联；焦点环明显；状态标签大多同时有文字。

主要风险：

- 多页签的主体是点击 `div`，不具备可靠的键盘 tab 语义；关闭按钮只在 hover 显示。
- 移动端关键操作被挤出视口，等同于键盘和触屏用户不可达。
- 色弱模式破坏对比度与语义色，不构成辅助功能。
- 中文界面中的弹窗关闭名称仍出现英文 `Close`；中英文切换后旧校验消息不刷新。
- 审计详情中的长 JSON / 方法串缺少换行、结构化语义与复制反馈。

## 证据边界

- 评审基于本地演示数据，用户、角色、配置等样本量较小；没有覆盖大规模分页和极长真实组织树。
- 为保护环境，未确认删除、权限覆盖、强退等破坏性操作，也未制造慢网络和后端失败。
- 可访问性结论来自截图、DOM 可访问性树和实现检查；未完成 NVDA / VoiceOver 全流程测试。
- PixelWave 在 8 秒连续采样中没有可见变化；能够确认“当前体验中不可见”，但无法仅凭截图断定是性能降级、设置状态还是渲染缺陷。
